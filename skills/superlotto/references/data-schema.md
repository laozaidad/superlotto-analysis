# 数据格式与获取边界

## 依赖的数据

本 Skill 只使用2023-01-01起（含当天，对应23001起）、严格早于用户指定目标期的大乐透历史记录。Skill目录不附带用户CSV或特定期次的固定推荐结果。网页另发布独立取得的公开历史快照，实际范围和来源以网页清单为准。

运行优先使用 `--data` 指定的 CSV；只有路径不存在时才获取500网数据。已存在但格式不合规的文件直接报错，不会被网络数据悄悄覆盖。

CSV 采用 UTF-8，允许 UTF-8 BOM。表头顺序固定：

```csv
No.,L1,L2,L3,L4,L5,R1,R2,Date
```

| 字段 | 要求 |
|---|---|
| `No.` | 五位期号字符串，例如 `23001`；保留前导0，不重复、按期号递增 |
| `L1`–`L5` | 1–35中的5个不同整数，升序排列 |
| `R1`–`R2` | 1–12中的2个不同整数，升序排列 |
| `Date` | ISO日期 `YYYY-MM-DD`；也接受可解析的ISO时间戳，日期须递增 |

号码可以是 `01` 或 `1`，读取为整数。抓取器输出两位号码与纯日期。期号不是浮点数；用电子表格处理时将其列设为文本，避免前导0丢失。已有CSV可保留更早年份的原始记录，输入审计仍可检查它们，但这些记录不会进入分析；不为实现范围限制而删除或改写原文件。

## 校验与数据质量

- 越界、少号、区内重复、未升序、重复期号、错误表头、日期不可解析或顺序错误均拒绝。
- 不同日期出现相同完整号码组可以是真实事件，只告警，不据此删行。
- 默认组合设计至少需要一条2023-01-01起且目标之前的有效记录；不足100条时使用本范围内真实可用数量计算冷热并提示局限。条件融合研究严格要求至少200条此前历史。不借用更早记录或补造记录。
- 缺少历史时，“从未出现”的遗漏只是至少等于已知历史长度。输出 `gap_censored=true`，不能把它当成完整历史下的精确遗漏。
- 校验数据格式不证明数据真实或完整。需核验源数据时，与开奖机构公开公告另行比对。

## 目标期与陈旧数据

对用户指定的目标 `target`，只有2023-01-01起且 `No. < target` 的记录进入模型。更早记录、已知目标期和未来期记录只能用于源文件完整性审计，不能用于频率、遗漏、上期重号、历史完整组合排除、形态或选号。范围内没有“上期”时不能从2022年及以前借用记录。报告旧记录与未来记录被排除的数量。

每次报告实际训练截止期及记录数。若同一年内目标期的前一期未出现，应说明数据可能陈旧或缺期；跨年期号不能简单对整数减1推断上一期，不能凭空制造期次。历史下载覆盖范围、目标附近是否缺期和全历史完整性是不同问题。

例如：准备分析某目标期但本地 CSV 截止更早，现有文件不会自动联网更新。要更新，明确发起抓取并使用新的文件路径，核对成功后再选择数据源，不混合来源后仍声称单一来源。

## 500网获取

来源入口：[https://datachart.500.com/dlt/](https://datachart.500.com/dlt/)。获取脚本根据该站历史数据页处理开奖记录，不从走势图的遗漏数字猜测开奖号码。

脚本运行需要可访问该公开站点。首次抓取保存原始来源说明，包括请求URL、抓取时间、内容或数据哈希、记录数、首末期、过滤数和完整性警告。网络抓取受站点可用性、页面结构和可查询范围影响，不能承诺任意未来目标的数据已经存在。

默认查询起点为23001，`--start` 早于23001时拒绝，而不是扩大分析范围。提供更晚起点只会减少有效样本。离线HTML导入同样剔除2023年以前的记录，并执行目标期和范围截断；不能利用离线入口绕过下限。

500网是第三方数据源，不是官方来源。使用时保留来源标签，不把抓取成功称作官方真实性核验。不要禁用TLS校验、绕过登录或验证码，或对被拒绝的接口无限重试。

网络失败或结构变更时：

1. 停止生成新的网络数据文件，不输出部分CSV冒充成功。
2. 告知失败环节，让用户提供合规CSV，或在浏览器保存500网历史记录页HTML。
3. 对用户提供的HTML离线解析时，仍记录文件哈希和来源性质；不得凭HTML文件名断言其真实性或完整性。

CLI 已有本地数据不自动刷新；实际刷新命令以 `scripts/fetch_data.py --help` 为准。需要覆盖现有文件时必须显式选择覆盖选项，不能把自动缺失补全当作任意覆盖授权。

## 网页公共历史定时维护

这属于完整仓库的维护流程，不是安装后每次运行 Skill 的隐含动作。GitHub Actions 每天北京时间／新加坡时间07:30、22:30检查独立公开数据；推送 `main` 和手动运行也会检查。仅纳入2023年起的数据；新候选必须保留已发布历史，拒绝删改旧开奖、缺期、非法号码和未来日期。无新增不写入、不创建空提交；只有新增且校验通过才提交公共产物。每次成功检查均验证并部署当前保存的版本，以恢复前次可能的部署失败。固定回测证据保持原样，不把新增数据回填成旧预测。

维护者可在完整仓库使用 `python3 scripts/update_history.py --site-dir site`。浏览器只读取已发布快照，不跨域抓500网、不自动刷新当前页面或重算旧结果；使用新数据需刷新网页再生成。此流程不读取或改写用户私人 CSV。

到 [Actions → Deploy analysis website](https://github.com/laozaidad/superlotto-analysis/actions/workflows/pages.yml) 检查实际结果或手动重试；手动取消 `refresh_history` 可用保留的数据发布代码修复。抓取、校验失败不提交；若推送成功而部署失败，仓库与线上截止期可能不同。定时任务可能延迟、被丢弃，公开仓库60天无活动时会停用，详见 [GitHub schedule 文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)。不承诺实时或官方完整性。

## 复现与发布

复现依赖相同数据内容、目标期、模型版本、随机种子、组数、模式及Python版本。种子相同但数据或实现变化，结果可能不同。

数据缓存、生成结果、抓取元数据及个人路径不应作为通用Skill源代码提交。仓库中的小型测试夹具只验证解析逻辑，不是可用于选号的数据后备库。

研究入口的固定规格、学习样本要求和时序协议见 [条件融合研究](research.md)。数据范围统一为2023起，不再接受旧版2013范围结果冒充本版本输出。
